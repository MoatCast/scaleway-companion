# Cloud Companion 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship five read-only features that need no new Scaleway permissions: per-resource cost, month-end forecast, invoices, Home/Lock Screen widgets and best-effort budget alerts.

**Architecture:** All new logic lives in small core files compiled by the Swift package and tested on macOS (`BillingSummary`, `Forecast`, `Invoices`, `SnapshotCache`, `Budget`). SwiftUI views stay thin. Widgets read a non-secret snapshot the app writes to a shared App Group container; the API key never leaves the app's Keychain item. Budget alerts run from `BGAppRefreshTask` and post local notifications; there is no backend.

**Tech Stack:** Swift 5 language mode, SwiftUI, Swift Charts, WidgetKit, BackgroundTasks, UserNotifications, XCTest. No third-party dependencies.

**Spec:** The 1.1 section of the review synthesis in this session (features 1–5) and the reviewer reports it summarizes; README.md for product principles.

## Global Constraints

- iOS 26.0 minimum, iPhone only, portrait. No new dependencies, no backend, no IAP.
- Permissions stay exactly `InstancesReadOnly` (selected projects) + `BillingReadOnly` (Organization). No task may change IAMSetupAPI policy rules.
- Money is `Decimal`, never `Double`, except for chart plotting. Amounts in different currencies are never summed.
- Billing months are UTC `yyyy-MM` strings; display through `BillingSummary.monthLabel`.
- Demo data never reaches the widget cache, budget state or notifications.
- Session tokens and API keys are never written outside the existing Keychain item (`KeychainCredentials`).
- Every new core file gets `// SPDX-License-Identifier: MPL-2.0` and is added to `Package.swift` `sources:`; every new SwiftUI-only file is added to `exclude:`.
- UI follows Paper: design each new screen in the "Scaleway companion" Paper file before coding it (Task 0).
- Copy: estimates say "estimate"; budget alerts say "best effort"; never imply real-time billing.
- Core tests: `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --scratch-path .build/unit -j 2`. Device build: the signed Release command in README "Build", with `DEVELOPMENT_TEAM` passed on the command line only.

## Review Focus

1. **Several currencies in one account** — forecast and budget act per currency; a EUR budget ignores USD lines. (Tests in Tasks 2 and 7.)
2. **Month boundary in UTC** — on the 1st the forecast is hidden and budget "already notified" state resets for the new period. (Tasks 2 and 7.)
3. **Disconnect or replacing the connection** — widget cache and budget state are cleared so a new Organization never shows the old one's numbers. (Tasks 5 and 7.)
4. **Background run while the phone is locked** — Keychain read fails (`WhenUnlockedThisDeviceOnly`); the task completes quietly, reschedules, and posts nothing. (Task 8; app-target code, so verified manually: simulate the task launch with the phone locked.)
5. **Consumption lines with empty `resource_name`/`product_name`** and invoice lists that are empty or paginated — grouped under "Other", empty states shown, no crash. (Tasks 1 and 3.)
